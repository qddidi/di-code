# WebUI 使用指南

di-code 有两种 Web 形态：`di-code web` 是本地同源 React 应用，负责浏览器界面；`di-code-webui` 是给嵌入式客户端使用的 HTTP/SSE 传输层。两者都复用 RPC Dispatcher、SessionHost 和 Agent loop。

## 本地 Web 应用

构建后从当前工作区启动：

```powershell
npm run build
di-code web
```

终端会打印 `http://127.0.0.1:<port>`。`--port` 接受 `0..65535`，省略或为 `0` 时选择可用端口；`--workspace <path>` 可重复传入额外工作区。默认只授权启动目录，附加目录必须已在 trust store 中信任。服务只绑定 loopback，收到 SIGINT/SIGTERM 会关闭。

开发模式同时启动 Web backend 和 Vite：

```powershell
npm run web:dev
```

`packages/web/scripts/dev.ts` 将 Vite 代理到临时 backend。可用 `DI_CODE_WEB_DEV_BACKEND` 指定 backend，`DI_CODE_WEB_DEV_ORIGIN` 指定 loopback origin；静态资源根目录通过 `DI_CODE_WEB_STATIC_ROOT` 覆盖。缺少 API key 时 Web 仍可用 Faux runtime 打开 Settings 完成配置，但 settings JSON 格式或安全校验错误会阻止启动。

## 页面与数据

SPA 通过同源 cookie 建立会话，浏览器不会拿到 provider key 或 transport token。首页按工作区显示 Session；会话文本与工作区内容左对齐，当前选中的 Session 使用高亮状态，任何仍在回复或执行工具的 Session 会在列表右侧显示旋转状态图标，即使用户切换到其他 Session 也会持续显示。普通 Session 的更多操作仅在鼠标移入或键盘聚焦时显示。顶部和工作区内的“新建会话”入口使用编辑图标。Chat/Trajectory tabs 展示消息、工具轨迹、上下文压缩和 usage。Composer 支持文本、最多四张图片、steer、cancel、retry、`/` 命令补全和模型/thinking/权限选择。回复进行中点击发送箭头仍会发送，并按顺序显示在提示词队列中；按 `Alt+S` 才会将内容作为 steering，引导队列会在对话区域持续展示。停止按钮内显示当前运行状态，独立的左侧 loading 图标不会重复出现。启用 Plan Mode 后，输入框底部工具栏会显示 `Plan` 胶囊，可用 `×` 退出；Plan 状态通过协商后的 `plan:mode` projection 恢复。Prompt、steer 或工具循环运行期间，对话末尾会保持 loading 指示，直到操作完成、取消或失败。启动、连接、会话和操作错误通过页面顶部居中的 Toast 显示，3 秒后自动消失，也可以手动关闭。窄屏时侧栏变为抽屉，`prefers-reduced-motion` 会关闭非必要动画。

Settings overlay 的 General、Models、locale、thinking、permission、Skills、MCP、Plugins、Trust 和快捷键视图都通过窄 RPC 读取脱敏 snapshot。环境变量托管的 key 只读显示；浏览器不能写入完整 settings JSON。已配置 Provider 可直接切换，未配置 Provider 才要求输入 key。

## HTTP 路由

本地 Web server 提供：

| 路由 | 用途 |
| --- | --- |
| `GET /api/boot` | 工作区、runtime、Session state、当前工作区 Session 列表和 RPC capability 快照 |
| `POST /api/workspaces` | 添加已授权的工作区路径 |
| `POST /api/workspaces/pick` | 打开本地目录选择器并添加工作区 |
| `POST /api/workspaces/rename` | 修改工作区显示名称 |
| `POST /api/workspaces/delete` | 删除当前 WebUI 的工作区注册 |
| `POST /api/rpc` | 版本化 RPC 请求 |
| `GET /api/events` | SSE 流式事件 |
| `POST /api/attachments` | 上传图片附件并返回 opaque handle |
| `GET /healthz` | 无认证健康检查 |

Settings、Provider、Skills、MCP、Plugins 和 Web contribution 通过 `/api/rpc` 的窄方法读取，不包含在 Boot 响应中。项目资源信任弹窗使用 `get_project_resource_summary` 一次读取 trust 和资源检测结果。内置 WebUI 使用 `get_session_snapshot` 一次读取当前 Session 页面所需的 state、Session 列表、首个 transcript 页面、tree、usage、context files 和 commands；transcript 仍通过 `nextPageToken` 分页。静态 `assets/` 使用 immutable cache，其余未知页面回退 `index.html`；`/api` 不参与 SPA fallback。服务器只向浏览器发送 opaque workspace/session/attachment ID，不发送绝对路径。扩展状态通过协商后的 `projection` 和 `interaction_request` 事件进入同一个 Web facade；旧客户端不会收到未协商的新事件。

## 嵌入式 HTTP/SSE WebUI

启动前必须设置至少 32 个字符的 token：

```powershell
$env:DI_CODE_PROVIDER = "faux"
$env:DI_CODE_WEBUI_PORT = "8787"
$env:DI_CODE_WEBUI_TOKEN = "replace-with-a-random-token-of-at-least-32-characters"
di-code-webui
```

可用环境变量：`DI_CODE_WEBUI_HOST`（默认 `127.0.0.1`）、`DI_CODE_WEBUI_PORT`（默认随机端口）、`DI_CODE_WEBUI_TOKEN`、`DI_CODE_WEBUI_ALLOW_REMOTE=1`。默认只接受 loopback 和同源 `http` Origin；远程绑定必须同时显式允许 remote、设置 token 并配置 `Origin` 白名单。token 只能通过 `Authorization: Bearer ...` 或 `X-Di-Code-Token` header 发送，不能放 URL、日志或事件。

客户端先连接 `GET /events`，从 `ready` 获取 `resumeToken`，再调用 `get_capabilities`。所有请求使用 `{ version: 1, kind: "request", id, method, params }`。事件带 sequence 和 `requestId`；断线重连时发送 `Last-Event-ID` 与 resume token。收到 `snapshot_required` 必须重新读取 snapshot，不要重放 prompt。

最小客户端见仓库 [examples/webui-client.ts](../../examples/webui-client.ts)。它演示 SSE、capabilities、Session、附件、prompt、steer、cancel、retry 和重连。

客户端断开后，服务端会释放该客户端拥有的 Session actor、MCP 连接和事件订阅，并取消未结束的运行。重连会建立新的客户端上下文；前端应重新读取工作区、Session、runtime 和资源快照，不要继续使用旧的 actor 状态。

如果要完全替换内置 React 页面，请阅读[从零开发自定义 WebUI 前端](自定义前端.md)，其中包含浏览器端 HTTP/SSE 客户端、RPC 方法和断线恢复示例。

## 安全与限制

每个 client 的 SSE、请求速率、附件数量和临时空间均有上限；附件在 client 专属目录保存并以 opaque ID 引用，过期后清理。认证客户端可请求工作区内文件工具和 shell，因此 WebUI 不是沙箱。远程开放等同于把本地编码能力交给持有 token 的客户端，只应在可信网络使用并限制 Origin。
