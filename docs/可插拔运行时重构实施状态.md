### Lifecycle/Security evidence

- 当前 Agent loop 的唯一执行者仍是 `@di-code/agent`；`AgentSession` 只组装工具并转发事件，RPC server 不实现第二套 loop。
- Session JSONL v2 追加、跨 manager lock、恢复诊断、branch context 和 compaction 语义已有测试；失败 append 不污染内存或后续队列。
- 文件工具使用 allowed-root canonicalization 并拒绝 parent traversal、外部绝对路径、外部/dangling symlink；bash 使用结构化 spawn 参数、明确 cwd、超时、取消和独立输出上限。
- 插件是同进程代码，不是沙箱；project trust 仅决定是否加载项目代码。manifest ID、entry root、权限声明、工具 namespace 冲突均校验，handler 诊断会脱敏 `token` 等凭据模式。
- MCP URL、headers、stdio command/args 由 MCP 包和宿主配置校验；连接失败只禁用对应 Server，并在结束时 close。
- RPC JSONL 校验版本、id/requestId、参数和事件；client 在子进程退出时拒绝 pending 请求，server 对并发 prompt 返回 `BUSY`，cancel 通过 AbortSignal 传播。
- TUI 测试覆盖 terminal startup failure 的状态回滚和 stop 幂等；orchestrator 只依赖公开 RPC SDK。

### Lifecycle/Security evidence

- 服务注册以 Fiber 为 owner；Fiber 进入 `active` 后才 commit，失败或卸载 rollback。迟到 callback 经过 Fiber 状态检查，不能在 `unloading`/`disposed` 中追加服务。
- Context dispose 先 abort 自身 signal，再逆序 dispose 子 Context 和 Fiber；Fiber dispose 等待 in-flight apply，之后逆序运行 disposer。重复 dispose 复用同一 promise。
- isolate Context 使用独立 registry，不能读取父 scope 的服务；普通子 Context 只通过父 Context 查询继承，不复制 registry。
- RuntimeEventBus 只用于观察和诊断，handler 错误隔离；插件仍是同进程代码，能力字段不是 Node 沙箱。

### Known risks

- `ServiceRegistry` 当前是最小 typed service registry，尚未提供 Loader 所需的依赖拓扑、optional injection、composition inventory 或跨 package registry 类型适配。
- `Context.plugin()` 当前只负责单个 fake definition 的激活，不负责 namespace/manifest、trust、capability gate 或动态 import；这些属于后续 Loader/SDK 阶段。
