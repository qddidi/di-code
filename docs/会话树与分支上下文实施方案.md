# 会话树与分支上下文实施方案

## 目标

为 interactive 模式增加内置 `/tree` 命令。用户可以浏览当前 JSONL Session 的完整对话树，选择任意历史节点后从该处继续；后续消息只使用该节点所在分支的上下文。历史记录始终只追加，选择节点、创建分支和恢复 Session 都不能删除或重写既有记录。

本方案以 `pi-main` 的 `/tree` 交互语义为目标，但保持 `di-code` 现有的包边界：树、持久化和上下文投影归 `packages/coding-agent` 所有，`@di-code/agent` 仍只接收完整的模型上下文，不感知 Session 树。

非目标：本阶段不增加跨 Session 树浏览、合并两个分支、删除节点、自动将分支写入新文件，或向既有 RPC 协议加入树导航方法。`/session` 继续用于在不同 Session 文件之间切换。

## 用户行为

`/tree` 只在 interactive 模式可用，并显示当前 Session 文件内的所有已提交节点。选择器至少显示节点类型、内容摘要、树形缩进和当前活动叶节点；`Enter` 确认，`Escape` 或 `Ctrl+C` 关闭且不改变 Session。

选择的节点决定编辑器和活动叶节点：

| 选择节点 | 新活动叶节点 | 编辑器 | 下次发送的上下文 |
| --- | --- | --- | --- |
| 用户消息 | 该消息的 `parentId`；根用户消息则为 `null` | 该用户消息的文本，可编辑 | 该用户消息之前的分支路径 |
| assistant、`tool_result` 或 `summary` | 所选节点 | 清空 | 包含所选节点的分支路径 |

用户修改并发送从编辑器恢复的用户消息后，新的 `message` 记录以当前活动叶节点为 `parentId`。因此同一父节点可以有多个子节点，原分支保留，新消息构成新分支。

带图片的用户消息只恢复文本部分；原图片附件不会自动重新发送，用户需要重新附加。这一行为需要在选择器和状态消息中明确，不能把磁盘中的图片数据悄然塞回编辑器或复制到新分支。

例如，当前活动叶节点为 `A4`，用户在 `/tree` 中选择旧用户消息 `U2`：

```text
U1 -> A1 -> U2 -> A2 -> U3 -> A3 -> U4 -> A4   当前分支
           |
           +-> U2' -> A2'                      新分支
```

选择 `U2` 后，活动叶节点变为 `A1`，编辑器显示 `U2` 的内容。提交修改后的文本会写入 `U2'`，而不会重复使用或覆盖原记录 `U2`。

## 会话格式

现有格式版本 `1` 记录了 `id` 和 `parentId`，但加载和追加要求每条记录的 `parentId` 都等于物理文件最后一条记录的 ID，因此实际是线性链。树形会话使用新的持久化格式版本 `2`，不兼容、不迁移 version `1` 文件。

版本 `2` 的约束如下：

- header 保持第一条记录，`type: "session"`、`parentId: null` 和 `id` 规则不变；`version` 为 `2`。
- 每个非 header 记录的 `id` 在整个文件内唯一。
- 每个非 header 记录的 `parentId` 必须引用 header ID 或已出现的 entry ID。header ID 表示根节点的父级，entry 不得引用尚未出现的记录或自身。
- JSONL 的物理顺序是追加顺序，不是活动分支顺序。后写入的记录可以引用较早节点，形成分叉。
- `summary.firstKeptEntryId` 必须是同一祖先路径上、位于 summary 之前的 `message` 记录；不能跨分支引用。
- 读到损坏、重复 ID、悬空父节点、环或不合法的 summary 引用时，保留此前已验证记录、生成 recovery diagnostic，并拒绝后续追加，沿用当前损坏恢复策略。

读取 version `1`、未知更高版本或非 `2` 的 header 时，一律以 `UNSUPPORTED_VERSION` 拒绝，且不修改原文件。用户需要重新创建 Session；旧 JSONL 仅可作为外部历史资料保留。Session 的公开类型、解码器和错误语义必须同步更新：`SESSION_FORMAT_VERSION`、`SessionHeader`、`loadSessionFile()`、`appendSessionEntry()` 与对应测试。

## SessionManager 设计

`SessionManager` 成为树的唯一所有者，保存以下运行时状态：

- `entriesById: Map<string, SessionEntry>`：按 ID 查询并校验父引用。
- `childrenByParentId: Map<string, string[]>`：生成树和子节点列表，子节点按 JSONL 追加顺序排序。
- `leafId: string`：当前活动叶节点；初始为文件物理末条 entry 的 ID，空 Session 时为 header ID。

不要把 `leafId` 写入 JSONL header 或 entry。它是当前进程的导航位置，不是共享持久化状态；不同进程可从同一文件选择不同分支。如果进程重启，默认恢复物理末端记录作为 leaf，与当前线性 Session 的恢复行为一致。

建议的内部接口：

```ts
get leafId(): string;
getTree(): readonly SessionTreeNode[];
getEntry(id: string): SessionEntry | undefined;
getBranch(leafId?: string): readonly SessionEntry[];
setLeaf(id: string): void;
resetLeaf(): void;
buildContext(leafId?: string): SessionContext;
```

`appendMessage()` 和 `appendSummary()` 必须从 `leafId` 取父节点，而不是从 `entries.at(-1)` 取父节点；成功追加后才将 `leafId` 前移至新 entry。若写入失败，内存 leaf 和上下文均保持原状。

`getTree()` 返回不可变快照，根节点是 `parentId === header.id` 的 entry。树遍历和分支路径构造必须迭代实现，避免长 Session 递归溢出。`getBranch()` 从 leaf 回溯到 header 再反转，不能按照物理 JSONL 顺序过滤，否则会把兄弟分支错误地送给模型。

## 上下文与压缩

`buildSessionContext()` 需要从“按 entry 数组投影全部消息”改为“先取当前叶节点祖先路径，再投影消息”。它必须同时返回与该路径对齐的 `sourceEntryIds`，供压缩准确定位 `firstKeptEntryId`。

上下文投影必须保留完整的工具调用批次。若选择的是含 `toolCall` 的 assistant entry，且该调用的 `tool_result` 尚未全部位于选择路径中，不能向严格 Provider 发出不完整的消息序列。实现应在确认导航前检测此情况，并将选择扩展到同一轮的最后一个对应 `tool_result`，或者拒绝导航并提示用户选择该轮最后一个结果；两种处理都必须在交互测试和 Provider 请求映射测试中固定下来。

压缩只作用于活动分支：

1. 从当前 `leafId` 得到根到叶的路径。
2. 在该路径上应用最新有效的 `summary`，保留 `firstKeptEntryId` 到 summary 之后的记录。
3. 仅把该范围中的 `message` 发送给模型；完整历史与其他分支继续留在磁盘上。
4. 新 summary 以活动 leaf 为父节点追加，并成为该分支的新 leaf。

切换到包含已有 summary 的分支时，必须重新从该分支路径构建上下文，不能复用之前分支的 `Agent.contextMessages`。`AgentSession` 在导航成功后调用 `agent.replaceContext(sessionManager.buildContext().messages)`；导航开始、压缩、模型请求和工具循环互斥，正在 streaming 时 `/tree` 必须拒绝或禁用。

本阶段不实现 Pi 的“离开分支摘要”提示。若后续增加，它应是新的 `branch_summary` entry 类型，以新分支起点为父节点，并在路径投影时显式转换成模型消息；不能把摘要塞进普通用户消息或覆写旧 summary。

## 并发与持久化

树允许 entry 的 `parentId` 与物理文件末条记录不同，但仍必须保护 append 的一致性。`appendSessionEntry()` 在拿到现有锁后应重新加载文件，并验证：

- 文件没有 recovery diagnostic；
- 待写 ID 未出现；
- 待写 `parentId` 已存在于 header 或已验证 entry；
- summary 的 `firstKeptEntryId` 位于该 summary 的祖先路径且是 message entry；
- 调用者期望的父节点仍存在。

不能再以“文件物理最后一条记录是否等于期望 parent”判断并发冲突：另一个进程在兄弟分支追加并不使当前父节点失效。追加成功后，当前进程将自己的 leaf 移到新 entry；其他进程下次追加前重新加载并根据自己的 active leaf 校验。

若远端进程追加导致本地 active leaf 的祖先路径被损坏或移除，加载校验会产生 diagnostic 并拒绝写入。正常 append-only 操作不会移除节点，因此这种情况只对应外部篡改或损坏。

## Interactive UI

在 `packages/coding-agent/src/modes/interactive.ts` 的内置 slash command 列表增加 `{ name: "tree", ... }`，并在命令分发中调用 `openTreeSelector()`。

新增专用选择器组件，保持 `@di-code/tui` 只负责展示和键盘输入。组件接收 `SessionTreeNode[]`、当前 `leafId`、选择回调和取消回调；它不读取文件、不改变 `SessionManager`、不调用 Provider。首版需要支持：

- 上下键选择，`Enter` 确认，`Escape`/`Ctrl+C` 取消；
- 多分支缩进、连接线、当前路径标记；
- 节点内容单行截断，tool result 和 summary 使用明确类型标签；
- 小终端下按可用行数滚动，且任意文本不能越过组件宽度。

确认选择后，由 interactive mode 调用 `AgentSession.navigateTree(entryId)`。该产品层方法负责验证空闲状态、按用户消息的特殊规则移动 leaf、替换 Agent 上下文、重新渲染当前分支消息，并返回可选 `editorText`。UI 仅把 `editorText` 写回编辑器。

完整分支树可作为既有 `/session` 的未来扩展，但 `/tree` 不依赖该工作。

## RPC、插件与可观察事件

当前公开 RPC 只有 `get_state`、`prompt`、`cancel`。本阶段不新增 tree RPC，避免在未定义并发导航和 client 交互模型前扩张协议。`get_state.messageCount` 的含义维持现状，即已加载的完整持久化消息数；如需暴露活动分支长度，应另加字段并保持 RPC `version: 1` 的向后兼容性。RPC 的版本号与 Session 文件版本独立。

插件命令不会自动获得 SessionManager 的树操作能力。若未来要提供插件 API，应在 `@di-code/coding-agent` 根入口定义明确的只读树快照和导航接口，以及重复调用、streaming、取消和错误行为；不要让插件导入 `src/core` 私有模块。

建议为交互投影增加 `tree_navigated` session event，至少包含旧 leaf、新 leaf、选择的 entry ID 和是否恢复编辑器文本。事件在上下文成功替换后发布；失败不发布成功事件。是否将它投影到 RPC 应在增加 RPC tree 方法时一并决定。

## 实施顺序

1. 定义 v2 JSONL 类型和严格解码规则；拒绝所有非 v2 文件，并先补存储层的树、损坏和并发测试。
2. 改造 `SessionManager`：维护索引与活动 leaf，支持树快照、分支路径和基于 leaf 的追加。
3. 改造 `buildSessionContext()`、压缩与 `AgentSession`：确保启动、导航、追加和 compaction 都只使用活动分支上下文。
4. 增加 `AgentSession.navigateTree()` 和它的 focused unit tests。
5. 新增树选择器、`/tree` slash command、虚拟终端测试和人工 TTY 验证。
6. 在实现同一变更中更新根 README、`packages/coding-agent/README.md`、CLI help/i18n 文案和会话格式说明；公共 API 或 RPC 有实际变化时再同步相关 README 与测试。

## 验收测试

实现完成前至少覆盖以下可观察行为：

- v2 文件加载有多个子节点的树，`getTree()` 和 `getBranch()` 返回正确父子关系与顺序。
- 从旧 assistant 节点导航后，新 prompt 只携带该节点祖先路径，不携带原活跃分支之后或兄弟分支的消息。
- 从用户消息导航后，编辑器恢复原文本，重新发送创建兄弟分支而不改写旧记录。
- 含图片的用户消息导航只恢复文本，并明确要求重新附加图片。
- 根用户消息可回退到空上下文并可创建新的根分支。
- 每个分支各自的 summary 只影响其祖先路径；切换分支后上下文、`sourceEntryIds` 和下一次 compaction 都正确。
- 选择带工具调用的 assistant entry 不会向 OpenAI 或 Anthropic 请求映射传入缺失 `tool_result` 的上下文。
- 两个 manager 在同一文件的不同父节点追加时都可成功；重复 ID、缺失父节点、无效 summary 引用、损坏记录和锁超时仍失败且不写入字节。
- version `1`、未知版本与损坏 header 均以 `UNSUPPORTED_VERSION` 或 `INVALID_HEADER` 拒绝，且不会修改原文件。
- `/tree` 出现在帮助与补全中；确认、取消、窄终端滚动和正在生成时的拒绝行为都有虚拟终端测试。
- `npm test --workspace @di-code/coding-agent`、`npm run check`、`npm run build` 和 `git diff --check` 全部通过。

## 风险与决策记录

`leafId` 不持久化意味着重启后默认落在最近写入的记录，而非上次在某个终端内查看的分支。这是有意选择：它避免多个进程争夺一个可变游标，并保留 JSONL 只追加的恢复性质。用户需要稳定保存分支位置时，应在后续以不可变 label entry 实现书签，而不是写入全局活动指针。

树形存储会使“物理最后一条记录”等同于当前上下文的假设失效。实现中所有上下文、压缩、用量统计、重试和 UI 重绘都必须明确选择完整历史还是活动路径；任何仍使用 `entries.at(-1)` 或 `entries.map(message)` 的位置都需要审查。

工具已经对工作目录造成的副作用不会随上下文导航回滚。`/tree` 只改变模型看到的对话路径，不能恢复文件、命令或外部服务状态；交互文案应避免暗示代码状态也会退回。
