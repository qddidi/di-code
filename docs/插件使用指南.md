# di-code 插件使用指南

di-code 插件是运行在本地 Node.js 进程中的 ESM namespace module。默认运行时由 Composition 将已启用的受管插件交给 `@di-code/plugin-loader`；Loader 校验 package export、namespace shape、依赖和 capability 声明，然后以 `@di-code/plugin-runtime` 的 `Context` 和 `Fiber` 管理生命周期。

插件 API 当前版本为 `1`。受管 package registry 是唯一的产品发现来源。

## 运行模型

插件通过公开 SDK 使用 `Context`、Service、Registry 和 EventBus 贡献运行时能力。实际能力可用性由已加载的 Composition、服务注入和 declared capabilities 决定；插件不能假定 CLI、Provider、会话、文件工具或 TUI 服务一定存在。

一个 enabled plugin 在加载时会经历 package metadata 校验、package export 解析、namespace module import 与 Fiber 激活。`disabled` 项不会解析或 import。required 项失败会中止 Composition 并回滚已激活项；optional 项失败会记录脱敏诊断并被跳过。Fiber dispose 会撤销其注册的服务、贡献和事件订阅。

插件在同一 Node.js 进程内执行，并不是沙箱。`permissions` 和 `capabilities` 用于 import policy、审计和 capability 服务门禁，不能阻止插件直接访问 Node.js 的文件、网络或进程 API。只安装可信来源的包。

## 创建包

发布或本地安装的插件必须提供 `package.json`，只声明一个公开 plugin export：

```json
{
  "name": "@acme/di-code-project-status",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    "./plugin": {
      "types": "./dist/plugin.d.ts",
      "import": "./dist/plugin.js"
    }
  },
  "diCode": {
    "apiVersion": 1,
    "plugins": ["./plugin"],
    "permissions": {
      "filesystem": "none",
      "network": [],
      "process": []
    },
    "capabilities": {
      "filesystem": true
    }
  }
}
```

`diCode.plugins` 必须恰好有一个字符串项，且该项必须在 `exports` 中声明。Loader 会拒绝空或错误的 `name`、`version`、权限、capability、API 版本、export target、绝对路径和包根外 symlink。包名去掉 npm scope 后成为受管 registry ID，例如 `@acme/di-code-project-status` 的 ID 为 `di-code-project-status`。

插件入口使用 namespace export，不能有 `default` export：

```ts
import type { Context } from "@di-code/plugin-sdk";

export const apiVersion = 1 as const;
export const name = "project-status";
export const version = "1.0.0";

export async function apply(context: Context): Promise<void> {
  void context;
}
```

插件类型从 `@di-code/plugin-sdk` 导入，运行时契约由 `@di-code/plugin-runtime` 提供，加载与 Composition 类型由 `@di-code/plugin-loader` 提供。不要从 `@di-code/coding-agent` 的内部路径、`src` 或 `dist` 导入。

## 安装和管理

受管插件位于用户目录 `~/.di-code/plugins/installed/<plugin-id>/`，registry 只加载 enabled 项。可以安装本地 package root、npm package 或 git URL：

```powershell
di-code plugin install D:\work\my-plugin
di-code plugin install npm:@acme/di-code-project-status@1.0.0
di-code plugin install git:https://github.com/acme/di-code-project-status.git

di-code plugin list
di-code plugin get di-code-project-status
di-code plugin disable di-code-project-status
di-code plugin enable di-code-project-status
di-code plugin update di-code-project-status
di-code plugin remove di-code-project-status
```

安装从 staging 目录开始。npm 使用固定 `--ignore-scripts` 参数；managed destination 经过 `resolve` 与 `relative` 边界检查；registry 通过临时文件替换写入；替换失败时恢复前一个已安装版本。`remove` 只删除 registry 中、且位于 managed root 内的插件。

`plugin get` 不显示安装路径、来源或凭据。运行 `di-code --trace-plugins` 或 `di-code --dump-composition` 可查看实际 resolved tree、Loader phase、owner Fiber、capability audit 和脱敏失败信息；它们不输出 entry config、安装路径、凭据或完整 Provider 请求。

## Trust 和安全

`--trust-project` / `--untrust-project` 管理项目 Skill 与 MCP 配置的导入资格，不会给予额外 Node.js 权限。非交互启动不会等待 trust 提示。

插件作者仍需为所有直接 I/O 负责：

| 场景 | 必须处理 |
| --- | --- |
| 文件 | allowed root、realpath/symlink、大小和编码限制。 |
| 子进程 | 固定命令和结构化参数、明确 cwd、超时、输出上限与取消。 |
| 网络 | 严格 URL/host 校验、超时和凭据脱敏。 |
| 外部输入 | schema 后的业务校验、边界和分页限制。 |
| 生命周期 | 将 disposer、订阅和异步工作归属到当前 Fiber；卸载后不再注册贡献。 |

不要在诊断、工具结果、错误或 Composition config 中写入 API key、Authorization header、token、secret 或完整请求体。插件的 handler 只应观察、记录和清理；它们不是第二套 Agent loop 或工具授权门禁。

## 排查

| 现象 | 检查 |
| --- | --- |
| 安装失败 | `package.json` 是否包含单个 `diCode.plugins` entry、相应 `exports` 和合法 API/权限声明。 |
| 插件未加载 | 检查 `di-code plugin list` 的 enabled 状态；disabled 项不会被解析或 import。 |
| Loader skipped/failed | 运行 `di-code --dump-composition`；处理 required dependency、namespace `name`/`apply` 和无 `default` export 要求。 |
| 能力不可用 | 检查 active Composition 是否提供所需 service、插件的注入声明及 capability policy。 |
| trust 不生效 | trust 只作用于项目 Skill/MCP；受管插件由 enabled registry 控制。 |

## 相关 API

- `@di-code/plugin-runtime`：`Context`、`Fiber`、Service、EventBus、Registry、capability 和诊断契约。
- `@di-code/plugin-loader`：package manifest/export 校验、Composition loader、trust store 和受管安装。
- `@di-code/plugin-sdk`：供外部插件使用的稳定根入口类型与运行时工厂。
- `packages/coding-agent/src/compositions.ts`：产品默认 `base`、`interactive`、`print`、`json`、`rpc` Composition。
