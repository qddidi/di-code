# 插件使用指南

第三方插件是可信的 in-process ESM 模块，只从 `@di-code/plugin-sdk` 根入口导入，并导出默认的 `setup(api)`。宿主在 import 前校验 manifest、精确版本、来源和完整性；版本不匹配会明确拒绝。

```js
export default function setup(api) {
	api.registerCommand({ name: "hello", description: "Say hello", run: async () => ({ version: 1, text: "Hello" }) });
	api.registerTool({
		name: "echo",
		description: "Echo input",
		schema: { type: "object", properties: {}, required: [], additionalProperties: false },
		execute: async (input) => ({ version: 1, content: input.parameters, truncated: false }),
	});
	api.registerSubagent({ name: "helper", description: "Run a child task", run: async () => ({ version: 1, taskId: "child", text: "done" }) });
	api.registerTuiOverlay({ name: "status", render: () => ["Ready"] });
	api.registerWeb({ entry: "./web.js", integrity: "sha256-...", slots: ["app.sidebar"] });
}
```

注册方法返回幂等 disposer，宿主在卸载时 abort `api.ctx.signal` 并清理所有注册。示例不需要处理 owner token、wire protocol 或重复 `dispose()`。

`api.ctx` 提供当前 Session、文件、subprocess、network、subagents、UI、settings、diagnostics、sessions、providers 和 jobs。宿主服务统一执行取消、超时、输出上限、结构化错误和生命周期回收；`providers.request()`、`subprocess.run()` 和 `jobs.start()` 在能力不可用时返回稳定错误，不静默降级。

Web bundle 使用独立 origin iframe 和版本化 bridge，只能读取宿主 projection、提交白名单 action；不得访问 Node 对象、Cookie、API key、绝对路径或内部 transport。需要真正隔离的不可信代码必须运行在独立进程、容器或虚拟机中。

manifest 至少包含 `apiVersion`、插件 `id`、精确 `version`、`entry`、`packageIntegrity` 和 `permissions`。Web 扩展额外声明 `entry`、`integrity`（SRI）和 `slots`。权限是安装提示和审计元数据，不是操作系统沙箱。

更多公共类型和版本化 Session/RPC/Web schema 见 `@di-code/plugin-sdk` 根入口及 `docs-vibecoding/plugin-freedom/`。
